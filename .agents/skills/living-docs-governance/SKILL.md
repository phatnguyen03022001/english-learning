# Living docs governance (adapted from ECC)
Activation: documentation, onboarding, layout or policy changes.
Input: current code/tests, canonical documents and Git history. Output: small verified edits to the existing owners.

Constitution: AGENTS.md. Map: README.md. Readiness: data/reviews/phase13/readiness-assessment.json (a dated snapshot).
History: Git and retained data/reviews evidence. Dictionary production rules: docs/lexical-production-contract.md.
Do not create a second architecture/status system, duplicate instructions or a phase log for routine changes.
Verify documentation claims against code and tests; history is data, not executable policy.
Human editorial status changes require their own authorized evidence and approval.
No global ECC checkout, Claude hooks, PRs or unavailable MCP is assumed.
